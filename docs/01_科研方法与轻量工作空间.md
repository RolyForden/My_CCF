# 科研方法、实验策略与轻量工作空间

> 来源：原《课程结构化校订稿》《Codex 科研方法深度剖析》《可复用科研 SOP》《科研 SOP 工作流设计说明》。
> 编辑原则：保留独有经验、判断、案例与可执行方法；合并同义表达；把旧 Gate/阶段机降为参考顺序，不再作为强制行政流程。

## 1. 一句话方法论

先锁定真实问题和最近邻证据，再写方法；先用低成本实验淘汰方向，再投入完整算力；先让主张经受反驳，再写论文。

Codex 的价值不是“替人做科研”，而是把人的会议经验、方向感和风险偏好变成约束，再承担搜索扩展、工程执行和材料整理。人仍必须决定：该怀疑什么、什么证据足以继续、何时停止，以及哪些结果在审稿语境中站不住。

## 2. 选题：约束先于搜索

选题前先写清：

- 目标 venue、年份、track、页数和截止时间；
- 公开数据、开源代码、硬件、预算和最长训练时间；
- 合作者、作者贡献和不可触碰的方向；
- 论文服务的长期能力，以及只为短期投稿服务的技巧。

这些约束把“什么最热门”改成“什么在当前可行域内最值得做”。信息不全时先补会改变结论的缺口，不急着写代码或命名方法。

### 2.1 广搜和深挖分开

1. 广搜阶段追求召回：目标会议近年题目、跨会议代表作、数据、代码和算力地图。
2. 深挖阶段追求证据：最近邻全文、方法与实验章节、官方代码、数据划分和真实限制。
3. 只让少量候选进入深挖，避免对每个方向都建立庞大文献工程。

近期强方法适合竞争性比较；简单或经典方法适合机制对照。不能因为模型老就机械排除，也不能因为模型新就默认更强。

### 2.2 判断方向所处阶段

不要只数论文数量。至少判断：概念提出期、快速扩张期、同质化期还是成熟期；代表工作解决了什么；剩余失败是否可测；代码和数据是否足以支撑本科生周期。

完全没人做可能是伪需求，太多人做可能已拥挤。较好的窗口通常是：任务已被证明重要、公开资产可用、具体机制问题刚开始有人触及。

### 2.3 主动攻击模型偏好

当模型反复推荐置信度、可靠性或热门模块时，主动追问：

- 这是任务真实矛盾，还是生成模型习惯性的安全答案？
- 最近工作是否已经直接覆盖？
- 为什么简单 baseline 不够？
- 什么结果会让我们放弃？

每个候选都要经过一次“为什么不该做”的独立审查。对话评分只能用于候选排序，不能解释为录取概率。

## 3. 从 gap 到候选 idea

一个候选至少包含：

```text
研究问题：要解释或改变什么现象？
可观察失败：现有方法在什么条件下失败？
机制假设：为什么发生？
最小实验：最便宜的决定性证据是什么？
最近邻：最可能覆盖主张的工作是什么？
简单替代：crop、重加权、普通 loss、强 baseline 能否解释？
资产：数据、代码、权重、算力和周期。
否定条件：什么结果出现就停止或降级？
拒稿攻击：审稿人最可能提出哪三个问题？
```

“创新是排列组合”只能作为工程启发。有效组合或迁移还必须回答：源问题与目标问题共享什么结构、假设哪里不同、为什么适用于当前失败、需要重新验证什么。成熟模块可以降低实现风险，不能保证组合有效或论文成立。

探索性实验可以帮助形成假设，但最终主张必须在独立样本或冻结协议上确认。不能先跑出模块，再从多篇论文中拼动机。

### 3.1 课程中的具体例子及正确解读

- Vision Mamba 的扫描顺序向低层视觉、遥感和高光谱迁移，说明“改变基础机制 + 找任务适配”可以形成早期窗口；不能简化成任意换扫描形状都能发表。
- PConv、AKCMamba-YOLO 等例子表面像换模块，正式工作还包含任务动机、结构设计、效率论证和多数据实验；课堂直觉不能替代完整证据。
- 点云恢复方向从置信度地点识别转向复合退化，说明候选排名会随查重和导师反证改变；早期高分不是方向成立。

## 4. Codex 的八种有效用法

1. **约束搜索**：提示中同时给目标、资源、排除项和交付物。
2. **先广后深**：先产生候选地图，再对少数最近邻阅读全文。
3. **攻击偏好**：要求模型检查自己是否习惯性推荐某类问题。
4. **构建时间线**：判断领域阶段，而不是只汇总论文数量。
5. **寻找迁移**：写明源问题、目标问题、共享结构、失效假设和官方代码。
6. **进入真实环境**：通过本地或 SSH 执行代码，但不把密码写入长期对话。
7. **分级实验**：单样本、proxy、全量逐步投入。
8. **形成可审查对象**：把聊天转成一页 idea、冻结配置、日志和结果，而不是继续增长对话。

所谓“多 Agent”通常只是检索、分析、反证、工程、审计和写作角色在不同任务中切换。关键是后一个角色有权否定前一个角色，而不是同时启动很多模型。

## 5. 证据与文献

- 摘要用于筛选，方法细节和新颖性判断回到全文或官方代码。
- 论文存在、方法细节正确、代码可用、实验可复现是不同层级的事实。
- 文献记录只保留会改变核心主张的证据；不为数量维护庞大矩阵。
- 无法获取全文时明确写“未核实”，不根据标题补全机制。
- 导师意见属于经验判断；若同时有论文、代码或实验支持，再升级为可核实事实。

## 6. Baseline：先证明链路可信

只优先选择代码、数据和评测入口可核验的 baseline。执行顺序：

1. 固定官方仓库 commit、checkpoint、数据来源和校验值。
2. 先跑单样本，检查输入、输出、NaN/Inf 和 shape。
3. 再跑 10%/20% proxy，快速判断工程链路与相对趋势。
4. proxy 通过后才投入完整 split 或完整训练。
5. 与论文数字比较时必须使用相同 setting 和 evaluator；差异只报告，不靠换配置追平。

baseline 能运行不等于完整复现，smoke test 能运行不等于方法有效。若为跑通而修改核心实现，不能继续称为官方复现。

## 7. Smoke、Proxy 与 Full

### Smoke test

极小 batch 或单样本，只检查数据、前向、反向、保存和评测链路。通过标准是“能正确运行”。

### Proxy experiment

10% 或 20% 子集是有效的成本控制手段：

- 按 shape、对象或研究单位采样，而不是随意抽 annotation；
- 冻结 seed、清单和采样规则；
- 报告分母、类别覆盖和缺失类别；
- baseline 与候选使用同一子集；
- 只改变一个核心变量；
- 预先写明继续、补证和停止表现。

子集失败不构成全量必败的数学证明，子集成功也不能替代全量论文证据。它的作用是快速筛选值得继续的候选。

### Full experiment

只有通过 proxy 的候选才跑全量。训练型方案应比较收敛结果，而不是固定 step；正式结果应覆盖强 baseline、简单机制 baseline、必要消融、公平性、效率、失败分析和研究问题要求的泛化。

随机性处理按实验风险决定：探索性筛选可固定并记录一个 seed；正式随机实验需要预先约定重复方式。不能通过反复换 seed 挑最好结果。

## 8. 实验的最低可追溯性

每个真实实验至少保留：

- 实际命令、冻结配置和代码版本/快照；
- 数据划分或样本 manifest；
- 数据和 checkpoint 校验值；
- stdout/stderr、机器可读指标和原始输出路径；
- 运行时间、显存及协议偏离；
- 失败结果，不覆盖、不静默删除；
- 图表对应的原始数据和生成脚本。

外部算力执行者只执行和交付，不替主研究者 commit、选择指标或解释论文主张。

## 9. 写作：主张驱动，而非模块驱动

常见引言结构仍然有效：

```text
背景 -> 近期工作 -> 可测失败/gap -> 方法 -> 贡献与证据
```

每个关键设计都应对应一个已观察的问题。贡献描述问题、机制和证据，不按模块数量凑数。先写方法、协议、结果和失败分析，最后写引言、相关工作、摘要和标题。

一篇论文的核心叙事应能压成一句话；三个贡献点可以是同一核心贡献下的问题发现、机制设计和实验验证，而不是三个无关卖点。

## 10. 轻量工作空间

长期结构只需要：

```text
AGENTS.md                 不易变化的底线
README.md                 工作区入口
docs/                     跨项目仍有价值的经验
templates/                真正复用的少量模板
scripts/                  确定性工具
projects/<topic>/         项目 README、证据、实验和论文
source_private/           不外传的原始材料
```

项目 README 是唯一当前状态入口，只写当前问题、已知/未知、真实结果、放弃条件和唯一下一步。实验开始后再建实验记录；写作开始后再建 claim-evidence 对照。旧版本交给 Git，不在活动目录堆叠多个阶段协议。

旧设计曾比较三种形态：单篇长文便于阅读但难更新；纯脚本启动快却会隐藏研究判断；文档 + 轻量脚本较适合当前学习阶段。现在进一步收缩为“少量长期文档 + 确定性脚本”，不再为每个阶段建 Gate 文件。

### 失败处理

- 论文无法取得全文：降低证据强度。
- baseline 无法复现：保留环境、命令和报错，不假装跑通。
- proxy 不通过：回到问题或停止，不改主张迎合结果。
- 结果无法稳定复现：不进入强主张写作。
- 数据、会议或截止时间不清：只补会改变决策的信息。

## 11. 与个人发展和合作的边界

工程线可以保留 ROS、SLAM、嵌入式、传感器和无人机闭环；论文线优先采用公开数据、可验证问题和开源 baseline。两条线共享领域直觉，不强迫一篇小论文承担完整系统复杂度。

合作中每个人应有可解释、可审计的真实贡献。导师解决高价值技术分歧，不替学生从零生成成品；Agent 降低重复劳动，不替人承担研究判断和作者责任。

会前材料保持一页：当前状态、关键证据、需要决定的事项、阻塞和自己的判断。会议只解决人才能判断的分歧，不把现场时间用于重读完整历史。

## 12. 结束时只沉淀四件事

1. 哪些判断正确；
2. 哪些判断错误；
3. 哪一步最耗时间；
4. 下一个项目应提前固化什么。

复盘应变成更短的规则，而不是新的流程层级。
