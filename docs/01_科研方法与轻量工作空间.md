# 科研方法与轻量工作空间

本文合并课程笔记、Codex 使用分析、旧科研 SOP 和工作区设计说明，只保留会持续影响研究判断与执行的内容。它是经验指南，不是必须逐项打卡的阶段机。

## 1. 核心原则

1. 先找到可观察的问题，再考虑方法；不要先拼模块再补动机。
2. 先查最近邻和官方代码，再判断 gap；搜索摘要只能用于筛选。
3. 先做最便宜、最可能推翻假设的检查，再投入完整训练。
4. 工程跑通、指标改善和科学主张成立是三件不同的事。
5. 任何关键主张都应能回答：什么证据会让我们修改或放弃它？
6. 精简管理文件，但不精简数据划分、baseline 公平性、日志和引用核验。

## 2. 选题方法

### 先约束搜索空间

选题前明确：目标 venue 与时间、公开数据要求、可用代码、GPU 与周期、合作边界、明确不做的方向。约束不是行政表格，而是为了尽早淘汰无法完成的题。

### 广搜与深挖分开

- 广搜阶段追求召回：候选方向、时间线、代表工作、数据与代码。
- 深挖阶段追求证据：最近邻全文、方法差异、实验协议和开源实现。
- 完全没人做可能是伪需求；太多人做可能已同质化。优先找已有任务基础、但具体失败尚未被解决的位置。

### 主动反证候选

每个候选至少回答：

- 现有方法在什么可测条件下失败？
- 失败是结构性问题，还是数据、分辨率、训练不足等简单原因？
- 最简单的替代解释或组合 baseline 是什么？
- 最近工作是否已经覆盖核心主张？
- 一个最小实验能否在一天或几天内决定继续/停止？

探索时可以从相邻领域迁移成熟机制，但必须写清源问题、目标问题、共享结构、不同假设和需要重新验证的部分。术语相似不等于可迁移。

## 3. Codex 的合适位置

Codex 擅长扩大搜索、整理候选、部署环境、批量执行、检查日志和形成可审查文本。它不能替代研究责任，也不能凭对话给出可信的新颖性或录取概率。

一次有效使用通常包含：

1. 给出目标、资源、排除项和真实交付物。
2. 先生成候选，再要求独立攻击候选。
3. 对关键论文回到正文或官方代码。
4. 让执行发生在真实环境中，并保留命令、配置和原始输出。
5. 由人决定研究问题、重大假设、停止条件和最终主张。

不要维护固定“科研内阁”。检索、分析、工程、审计和写作只是临时角色；只有任务能够独立执行且产物明确时才并行委派。

## 4. 最小科研循环

### 定问题

在项目 `README.md` 中写清当前问题、已知事实、未知项、放弃条件和唯一下一步。问题写不清时先讨论，不命名方法。

### 查最近邻

优先找最可能覆盖当前主张的工作，而不是堆大量宽泛引用。只有会改变判断的证据才进入项目证据文件。

### 做最小判别

优先顺序通常是：数据审计、单样本、官方 checkpoint、小规模行为检查、20% proxy、完整确认、方法训练。上一项足以否定假设时立即停止。

### 再决定

结果只导向三类动作：继续、修改问题、停止。只有判断发生变化时才更新 README 或重大决策记录。

## 5. 实验层级

### Smoke test

用单样本或极小 batch 检查数据、前向、反向、保存和评测链路。通过只代表能运行。

### Proxy experiment

10% 或 20% 子集可以用于快速筛选。子集应按研究单位采样并冻结规则，尽量覆盖主要类别；需要记录 seed、分母和缺失类别。proxy 通过可放行全量，不能直接替代完整论文证据。

### Full experiment

只给通过 proxy 的候选投入全量。训练型方案应比较收敛结果，而不是用同一固定 step 草率排名。baseline、数据划分、评测预算和选择标准不得根据结果静默改变。

### 结果要求

正式实验至少能够追溯到：

- 代码版本或代码快照；
- 数据与 checkpoint 校验值；
- 实际命令和冻结配置；
- 数据划分或样本 manifest；
- stdout/stderr 和机器可读指标；
- 失败或协议偏离；
- 图表对应的原始结果与生成方式。

## 6. 工作区设计

工作区只保留四类长期资产：

- `docs/`：跨项目仍有价值的经验与边界；
- `templates/`：真正复用的最小模板；
- `scripts/`：确定性的初始化、验证和构建工具；
- `projects/<topic>/`：项目 README、必要证据、实验与论文产物。

`source_private/` 保存不进入外部服务的私密材料。数据、权重、环境缓存和大体积中间结果不进入 Git。

项目当前状态只维护在项目 README。实验开始后才增加实验目录；写作开始后才增加 claim-evidence 对照。旧版本由 Git 保存，不再为了“可能回看”长期堆在活动目录。

## 7. 写作与复盘

论文主线应满足：

```text
问题证据 -> 机制假设 -> 方法或干预 -> 公平比较 -> 限制
```

先写方法、实验协议、结果和失败分析，最后写引言与摘要。探索性结果与确认性结果必须分开，不能从多个文献中拼动机为已完成模型补故事。

项目结束只复盘四件事：哪些判断正确、哪些判断错误、哪里最耗时间、下个项目需要提前固化什么。复盘应转化为简短规则，而不是新的流程层级。
