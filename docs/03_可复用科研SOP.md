# 可复用科研 SOP

## 总原则

先锁定问题和证据，再写方法；先复现 baseline，再谈改进；先用低成本实验淘汰方向，再投入完整算力；先让主张经受反驳，再写论文。

## Phase 0: INTAKE - 研究约束

**输入**：个人背景、目标会议、截止日期、时间、GPU、数据、合作者和禁止项。

**产物**：`RESEARCH_CHARTER.md`。

**必须回答**：

- 目标是算法论文、系统论文、数据集/benchmark 还是应用验证？
- 准确的会议、年份、track、页数和截止日期是什么？
- 可用算力、总预算、最长训练时间和存储是多少？
- 是否必须使用公开数据？是否允许生成合成数据？
- 哪些能力服务未来方向，哪些只是短期投稿技巧？

**Gate G0**：问题、会议和资源任一不清楚，禁止开始写代码。

## Phase 1: LANDSCAPE - 文献地形

**步骤**：

1. 先检索目标会议近 3 年题目与摘要，建立方向分布。
2. 再检索目标方向近 3 年的跨会议代表作。
3. 对候选论文记录：问题、假设、数据、指标、代码、算力、局限、证据等级。
4. 只对进入短名单的论文阅读全文；摘要阅读不得伪装成全文阅读。
5. 构建时间线：提出期、扩张期、同质化期或成熟期。

**产物**：`LITERATURE_MATRIX.csv`、`EVIDENCE_LEDGER.md`、`LANDSCAPE.md`。

**Gate G1**：至少确认主要工作、最接近工作和代码/数据现状；核心 gap 不能只来自搜索摘要。

## Phase 2: IDEA - 候选与反证

每个 idea 使用同一张卡片：

- 一句话研究问题。
- 现有方法在何种可测条件下失败。
- 为什么这个失败对目标领域重要。
- 方法机制如何对应失败原因。
- 可证伪主张是什么。
- 最小实验是什么。
- 最近重复工作的风险。
- 数据、代码、算力和周期。
- 三个最可能拒稿理由。

至少生成 3 个候选，再由独立 Skeptic 角色攻击。排序使用：问题价值、查重新颖性、证据可得性、baseline 可复现性、4090 可行性、周期、与你未来方向的连续性。

**Gate G2**：必须有明确否定条件。没有“什么结果会让我放弃”，就不是可检验 idea。

## Phase 3: BASELINE - 复现

**步骤**：

1. 固定官方仓库 commit、环境、数据校验和评测脚本。
2. 先跑官方最小示例，再跑目标数据集的小规模流程。
3. 将复现结果与论文数字比较，解释差异。
4. 记录显存、速度、训练时间、参数量和失败日志。
5. 不改动 baseline 的核心实现来“帮助它跑通”后仍称官方复现。

**产物**：`BASELINE_REPRO.md`、环境锁文件、命令、日志、原始指标。

**Gate G3**：baseline 未跑通，方法改造原则上暂停；若因官方代码缺失而继续，必须降低主张并记录风险。

## Phase 4: PILOT - 低成本试验

### 4.1 Smoke test

用极小 batch、少量样本和 1 到 2 个 epoch 检查完整链路。通过标准是“能正确运行”，不是“指标提升”。

### 4.2 Proxy experiment

- 预先固定代表性子集与 seed。
- 同时跑 baseline 和候选方法。
- 只改变一个核心变量。
- 记录训练曲线、稳定性、显存和错误样例。
- 预先定义继续阈值，例如相对提升、稳定性或效率目标。

**Gate G4**：趋势不稳定、机制消融不支持或成本超标，回到 IDEA；禁止靠多次换 seed 挑好结果。

## Phase 5: FULL_EXPERIMENT - 完整实验

**实验包至少包含**：

- 主结果：最近强 baseline + 简单机制 baseline。
- 消融：每个声称的设计都有独立对照。
- 公平性：统一数据划分、预处理、训练预算和评测脚本，或解释无法统一的原因。
- 稳定性：对随机方法运行预先约定的多个种子并报告均值/离散性。
- 效率：参数、FLOPs/推理时间、峰值显存和训练成本。
- 失败分析：方法在哪些样本和条件下失败。
- 泛化：只有在研究问题需要时才加入跨数据集、跨类别或真实域验证。

**产物**：`EXPERIMENT_REGISTRY.csv`、配置、日志、结果、图表脚本和 `RESULTS_AUDIT.md`。

**Gate G5**：所有论文数字能从注册表追溯到原始文件；无法追溯的数字不得进入论文。

## Phase 6: WRITING - 主张驱动写作

先写 `CLAIM_MATRIX.md`，再写正文。每条贡献都要对应：

`问题证据 -> 方法机制 -> 实验比较 -> 限制`

推荐顺序：

1. 用一句话写核心可证伪主张。
2. 写图 1：问题、旧方法失败、方法直觉。
3. 写方法与实验协议。
4. 写结果和失败分析。
5. 最后写引言、相关工作、摘要和标题。

**Gate G6**：没有证据的形容词删除；引用未核验、数据来源不清、探索性结果被写成确认性结论时禁止进入评审。

## Phase 7: REVIEW - 双重红队

第一轮按目标会议审稿维度检查：相关性、新颖性、技术正确性、实验充分性、清晰度、可复现性和伦理。

第二轮只检查第一轮修改是否真正解决问题，重点寻找：

- 新增主张没有新增证据；
- 通过改措辞掩盖方法局限；
- baseline 或数据划分不公平；
- 引用只支持邻近观点，不支持当前句子；
- 图表与正文数字不一致。

**Gate G7**：会议政策、匿名、页数、AI 使用披露、作者贡献和所有引用通过核对后才提交。

## Phase 8: ARCHIVE - 复利

无论录用与否，保存：最终代码 commit、环境、数据说明、实验注册表、投稿版本、审稿意见、回复、失败实验和复盘。

复盘只回答四个问题：什么判断是对的，什么判断错了，哪一步最耗时间，下一个项目应提前固化什么。

## 每周节奏

- 周一：确认本周唯一阶段目标和 Gate。
- 周二至周四：执行、记录，不频繁改叙事。
- 周五：opencode 做证据与日志审计。
- 周末：你和合作者/博士只讨论需要人判断的分歧，并形成会议纪要和明确 owner。

## 与博士合作的边界

每次会前提交一页材料：当前状态、证据、三项决策、两项阻塞和你自己的判断。会议只解决高价值分歧，不让博士现场替你从零想题。

付费指导应交付方法、反馈和可解释的判断，不应交易“保证录用”。作者资格取决于真实学术贡献。所有关键决定写入 `DECISIONS.md`，避免后期对贡献和方向产生争议。
