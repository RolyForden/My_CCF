# Codex 科研方法深度剖析

## 一句话判断

这位博士不是在用 Codex “替他做科研”，而是在把自己已有的会议经验、方向感和风险偏好变成一组约束，让 Codex 负责扩大搜索、生成候选、执行工程和整理文书。他真正不可替代的部分仍是：知道该怀疑什么、何时否定一个方向、什么证据足以继续，以及哪些结果在审稿语境里站不住。

## 他实际使用的八个手法

### 1. 约束先于搜索

首个提示里同时给出 IJCNN 2027、LiDAR/IMU/Vision、公开数据、不碰硬件、单卡 4090、较短周期和创新空间。这使 Codex 不是回答“什么最热门”，而是在有限可行域中排序。

**可复用点**：提示词必须包含目标、资源、排除项和交付格式。没有这些，模型只会给泛泛趋势。

### 2. 先广搜，再选一个方向深挖

他先让 Codex 给多个候选与综合排名，再只围绕一两个方向讨论。这避免了过早陷入某个模型细节。

**可复用点**：广搜阶段追求召回率，深挖阶段追求证据质量，两者不能混在一个提示里。

### 3. 主动攻击模型的偏好

当 Codex 反复推荐“置信度/可靠性”时，他没有接受，而是问：是不是模型习惯性喜欢这个词？是否已经有人做？太多人或完全没人做分别意味着什么？这个动作迫使模型从生成模式切换到反证模式。

**可复用点**：每个候选 idea 都必须经过一次独立的“为什么不该做”审查。

### 4. 用“当前阶段”判断机会，而不只看论文数量

截图中他追问方向从 2024 到 2026 解决了哪些 gap，现在处于概念提出、快速扩张、同质化还是成熟阶段。这个问题比“有没有论文”更有用。

**可复用点**：趋势判断至少要包括时间线、代表工作、已解决问题、尚未解决问题和开源成熟度。

### 5. 从邻域寻找迁移与工程兜底

他要求 Codex 检查图像恢复、组合学习、UOT/WFR、可变基数过程等相邻方向，寻找可以迁移的机制和代码。目的不是堆名词，而是让新问题建立在已被其他领域验证的思想上。

**可复用点**：迁移必须写清“源问题 - 目标问题 - 共享结构 - 不同假设 - 需要重做的验证”。没有这五项，只是类比。

### 6. 把 Codex 放到真正的执行环境中

他通过 SSH 让 Codex 在云服务器上拉仓库、配环境、改代码、运行和监控。CPU/无卡时做工程准备，GPU 时只做训练和评测。这是很现实的成本优化。

**可复用点**：先把运行命令、环境锁定、数据校验和日志路径写清，再让 Codex 执行；不要把密码贴进会长期保存或外发的对话。

### 7. 分级实验，而不是一开始全量训练

他的 20% 数据思路本质是建立 proxy task。方向正确，表述过度绝对。

**可复用点**：将其升级为 smoke/proxy/full 三阶段，每阶段有不同目标和通过条件。

### 8. 强制生成结构化 idea report

最后要求输出题目、相关工作、gap、方法、创新点、baseline、数据集和算力。这将讨论从聊天转成可审查对象。

**可复用点**：任何 idea 在进入代码前，都必须能写成一页“可证伪设计”，而不是只有模块图。

## 他的“多 Agent”本质

截图中并没有一个神奇的全自动团队，更像同一 Codex 在不同轮次切换角色：

1. `Scout`：扩大论文和方向召回。
2. `Cartographer`：画出近年趋势、数据、代码和算力地图。
3. `Generator`：提出候选 gap 与方法。
4. `Skeptic`：找重复工作、伪 gap 和最可能拒稿点。
5. `Transfer Analyst`：寻找相邻领域可迁移思想。
6. `Engineer`：部署仓库、复现、跑试验。
7. `Auditor`：检查公平性、数据泄漏、日志和稳定性。
8. `Writer/Reviewer`：形成论文结构并反向攻击主张。

关键不是同时开八个模型，而是角色之间传递固定产物，并让后一个角色有权否定前一个角色。

## 哪些地方容易被误学

### “Codex 能完成 90% 工作”

按文件数量或命令数量，它可能完成 90%；按研究责任，它不能。数据泄漏、错误指标、baseline 不公平、训练失效、引用错配和过度主张都可能产生表面漂亮的结果。人必须能回答每个核心设计为什么存在，并能复查关键代码路径。

### “近期 baseline 一定优于老模型”

近期模型更适合说明当前竞争，但经典 baseline 可能对应更清晰的因果对照。正确做法是：最近强方法用于竞争性比较，简单/经典方法用于机制与消融，二者都不能机械排除。

### “成熟模块组合能保证效果”

成熟模块分别有效，不代表组合后有效。目标函数、数据分布、特征尺度和优化动态都可能冲突。组合只能降低实现风险，不能保证论文主张。

### “先跑出效果，再补动机”

这是最危险的一条。探索性实验允许帮助形成假设，但最终主张必须重新预注册、在独立验证上检验，并诚实区分探索与确认。

### “一个模型评分就是会议概率”

截图中的 7.5/10、8/10 只是对话式启发，不是经过校准的录取概率。它适合比较候选，不适合下注。

## 对你最合适的用法

你现在需要的是“保留领域连续性，降低实验不可控性”。最佳组合是：

- 用你的 SLAM、点云和嵌入式经验判断问题是否真实；
- 用公开数据和开源 baseline 承担论文主证据；
- 用 Codex 承担文献矩阵、环境部署、批量实验、日志审计和写作检查；
- 让博士承担方向校准、关键技术判断和阶段评审，而不是替你交付成品；
- 让你和同学分别拥有可审计的真实贡献，避免“付费买结果”的合作结构。

这比纯做任意二维 AI 更适合你的未来，也比强行依赖无人机实采更容易在大二阶段完成。

## 一个合格的 Codex 会话应留下什么

不是一大段回答，而是以下可复用资产：

- 经核验的文献矩阵与全文阅读状态；
- 候选 idea 的淘汰记录；
- 可运行的 baseline 命令、环境和日志；
- 预先定义的实验比较与通过条件；
- 每个图表对应的原始结果和生成脚本；
- claim-evidence 矩阵；
- 会议政策和格式核对清单；
- 失败复盘。

这些资产齐全，才叫 agentic research；否则只是让模型陪你聊科研。
