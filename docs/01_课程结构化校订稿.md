# 课程结构化校订稿

> 这不是逐字稿，而是依据录音与截图重建的结构化课堂笔记。讲者观点与本项目的批判性修正分开呈现。

## 1. 课程主线

课程想传达的是一套面向普通算力、公开数据和较短周期的 AI 论文工作流：观察新架构或热门机制，寻找尚未拥挤的迁移空间，用 Codex 做文献检索、候选方案整理、代码部署和实验执行，再围绕 gap、motivation、method、contribution 完成论文叙事。

讲者用三组例子说明这一点：

1. Vision Mamba 的扫描顺序及其向低层视觉、遥感和高光谱任务迁移。
2. PConv 和 AKCMamba-YOLO 这类结构模块在特定任务中的改造。
3. 点云恢复候选方向，从置信度地点识别逐步转向未见复合退化与可组合恢复。

## 2. 选题与创新

### 讲者的原始策略

- 关注刚兴起的基础架构或机制，早期窗口往往允许较小改动。
- 从相邻领域迁移已经成熟、开源且有性能基础的做法，以降低执行风险。
- 较稳妥的中间路线不是从零发明，也不是简单串联模块，而是从两个成熟模型抽取有效部件，再设计自己的连接或交互结构。
- 选题要同时考虑新颖性、目标会议匹配、公开数据、开源代码、周期和算力。
- 近两年论文比很老的经典 baseline 更能反映当前审稿环境。

### 必要修正

“创新是排列组合”只是一种工程启发，不是学术定义。有效迁移至少要回答：为什么原机制适合新问题、旧方法在哪个可测条件下失败、迁移后产生了什么新的可证伪命题、是否有公平对照与消融。仅有模块替换和指标上涨，很容易被判为增量拼装。

PConv 和 AKCMamba-YOLO 的正式论文也不只是换形状或换模块；它们同时包含任务动机、结构设计、效率论证、数据集或多数据集实验。课堂为了讲清直觉做了压缩，不能把压缩后的版本当作完整科研标准。

## 3. Codex 选题循环

从截图可以还原出讲者采用的提示链：

1. 给出目标会议、年份、领域、资源和不想涉及的内容。
2. 要求 Codex 检索近两年题目分布并对候选方向排序。
3. 选中方向后，追问领域目前处于什么阶段、主流在解决什么、还剩什么 gap。
4. 反驳 Codex 的首选。例如质疑它是否习惯性推荐“置信度/可靠性”，要求自查该方向是太冷、太热还是刚好。
5. 要求从相邻领域寻找可迁移机制、代码和公开数据，以形成执行兜底。
6. 追问 baseline、数据集、训练配置、显存、时间和失败点。
7. 要求生成 idea report，包含相关工作、gap、方法、创新点、baseline 和数据集。

这不是一次“神提示词”，而是生成者与批评者交替的回路。真正有效的动作是持续追问证据和否定条件，而不是让模型把答案写得更长。

## 4. 实验与算力

### 讲者的做法

- 在租用服务器的无卡/CPU 模式中完成仓库拉取、环境配置和代码改动。
- 只有训练和评测时开启 GPU，跑完及时关机。
- 通过 SSH 让 Codex 直接在服务器目录中工作、运行和监控实验。
- 先抽取约 20% 训练数据筛选方案，再决定是否跑全量。

### 修订后的三段式实验

1. **Smoke test**：极小数据与极少迭代，只检查数据、前向、反向、保存和评测链路。
2. **Proxy experiment**：固定且具有代表性的子集，用于比较候选方案的相对趋势。需要固定 seed、采样规则和预注册阈值。
3. **Full experiment**：全量数据、正式训练计划、多种子或必要的重复运行，才用于论文主张。

子集失败不证明全量必败，子集成功也不保证全量成立。小数据会改变类别分布、难例比例、优化动态和模型缩放行为。20% 是成本控制手段，不是科学定律。

## 5. 论文叙事

课程给出的常见引言结构是：

`背景 -> 近期工作 -> 未解决问题 -> 我们的方法 -> 贡献`

其中 gap 是连接方法与贡献的中轴。方法中的每个关键设计都应对应一个已证明存在的问题；贡献则应描述问题、方法和证据，而不是模块数量。

需要纠正的一点是：不能从多篇论文中“拆一点动机”来给已经跑出的模型补故事。可以综合文献形成研究背景，但必须准确引用，并在实验前形成可证伪主张。否则会变成结果导向的事后叙事。

## 6. 讲者工作流的真实价值

他实际上做了四层压缩：

- **认知压缩**：先用目标会议和资源砍掉大量不合适方向。
- **证据压缩**：让 Codex 从近年论文、代码和数据中生成候选地图。
- **工程压缩**：让 Codex 通过 SSH 操作环境和实验，减少人工重复劳动。
- **叙事压缩**：用固定论文结构把 gap、方法和证据串起来。

这四层值得学习，但每层都必须加审计：文献要核原文，代码要核实现，实验要核公平性，写作要核主张与证据。

## 7. 对唐卓当前情况的适配

更适合你的不是完全离开机器人去做任意 AI，而是把论文主线调整为“公开数据 + 算法问题 + 可复现代码”，保留 LiDAR/点云/定位导航这一领域连续性。无人机和 SLAM 项目继续作为工程能力与问题直觉来源，但论文不能依赖难以稳定获得的自采数据。

可以并行维护两条线：

- **工程线**：ROS2、Fast-LIO2、RK3588、传感器接入、无人机闭环，服务简历与面试。
- **论文线**：公开数据集、可验证的新问题、开源 baseline、4090 可承受实验，服务研究训练与保研材料。

两条线可以共享领域语言和应用动机，但不强迫同一篇小论文承担整个无人机系统的复杂度。
