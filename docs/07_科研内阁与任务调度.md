# 科研内阁与任务调度

## 目的

把 opencode 主会话当作研究运行空间，而不是聊天收藏夹。当前文件夹保存长期资产；主会话（总控台）维护研究全局；`.opencode/agent/` 下的专项 subagent 只完成被委派的、可验收的工作。

## 总控台

主会话即「科研总控台」。总控台负责：

- 读取并维护 `projects/<topic>/STATE.yaml`、`RESEARCH_CHARTER.md`、`DECISIONS.md`。
- 判断新问题属于文献、数据、选题、工程、写作还是需要博士判断。
- 只在任务独立、产物明确时委派专项 subagent，避免为每个念头新开一个 subagent。
- 接收专项 subagent 的回传，更新证据账本、Gate、优先级和下一步。
- 将博士建议登记为“导师判断”，与已核验事实、待验证假设明确区分。
- 在冲突时先保护研究完整性、可复现性和你的长期方向，而不是迎合某个短期指标。

总控台不直接替代专项深挖，也不把未验证的 subagent 输出写进研究结论。

## 派单协议

总控台调用专项 subagent 时，任务说明必须写清：

1. 当前项目路径和 `STATE.yaml` 阶段。
2. 唯一研究问题或交付目标。
3. 可用材料与不可访问的私密材料。
4. 证据标准和停止条件。
5. 产物文件路径与回传格式。

示例：

```text
你是“文献情报｜研究内阁”。当前项目为 [项目路径]，阶段为 LANDSCAPE。
目标：核验近三年 [方向] 在 [会议] 与相邻顶会的代表工作，不提出新模型。
只使用官方 proceedings、论文 PDF、作者项目页和官方仓库。截图/摘要只能作线索。
输出：更新 01_landscape/LITERATURE_MATRIX.csv 和 EVIDENCE_LEDGER.md，并回传已核实结论、待核项和是否满足 G1。
不要改动 RESEARCH_CHARTER.md、STATE.yaml 或 DECISIONS.md；关键决策交给总控台。
```

## 回传协议

专项 subagent 结束时只回传以下六项：

```text
状态：完成 / 部分完成 / 阻塞
已核实事实：每条带证据等级和文件位置
待验证假设：不可写成结论的内容
关键风险：最多三项
建议决策：继续 / 补证 / 淘汰，以及理由
产物：已更新的文件和下一步最小行动
```

总控台收到回传后决定是否更新 `STATE.yaml`。专项 subagent 无权自行推进 Gate。

## 博士在内阁中的位置

博士不是一个被模拟出来的“权威 Agent”，而是外部技术顾问。总控台将其意见写入会议纪要和决策账本，标注为：

- `导师判断`：经验性建议，通常是 C 级证据。
- `可核验事实`：有论文、代码、日志或官方政策支撑，按 A/B 级记录。
- `待验证假设`：需要实验、全文阅读或复现才能成立，按 D 级记录。

这能保留他的价值，也能避免“他说过”替代证据。

## 私密边界

- `source_private/` 的录音、截图和未发表材料默认仅供总控台在必要时查看。
- 专项 subagent 不应被要求转述、复制或外传未发表内容。
- 账号、SSH 密码、API key、私人聊天记录不放进对话 prompt 或项目文件。

## 当前推荐启动顺序

1. 在 opencode 中打开本目录（`Z:\科研总控台opencode`），主会话即总控台。
2. 总控台先完成 `20260902-CCFC选题` 的 G0：目标会议、截止日期、预算和分工。
3. 只有 G0 通过，才委派 `文献情报` 与 `数据与基线`。
4. 选题通过红队后，才委派 `工程实验`；写作任务留到已有证据之后。
