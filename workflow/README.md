# 轻量科研循环

这不是阶段机。研究可以往返，也不要求每轮生成新文件。

## 1. 定问题

在项目 `README.md` 写清：当前问题、为什么值得查、什么结果会让我们放弃。写不清时先讨论，不急着命名方法。

## 2. 查最近邻

先找最可能覆盖当前主张的工作。摘要用于筛选，方法和新颖性判断回到正文或官方代码。只记录会改变判断的证据。

## 3. 做最小判别

优先选择最便宜、最可能推翻假设的检查：数据审计、单样本推理、官方 checkpoint、反例或小规模诊断。不要用大实验替代问题定义。

## 4. 再决定

结果只导向三种动作：继续、修改问题、停止。只有决定发生变化时，才更新项目 `README.md` 或 `DECISIONS.md`。

## 何时增加记录

- 文献开始影响核心主张：维护 `EVIDENCE.md` 或项目已有的文献表。
- 开始运行实验：使用 `templates/experiment.md`，记录命令、配置、代码版本、数据划分和原始结果。
- 准备写论文：再建立 claim-evidence 对照，不提前生成空表。
- 投稿前：集中核对会议政策、匿名、页数、引用、作者贡献和 AI 使用要求。

## 每轮输出

默认不超过三段：新发现、判断变化、唯一下一步。

复杂报告、PDF、红队清单和并行 agent 只在它们能帮助具体决策时使用。
