# 科研 SOP 工作流

这是把 2026-09-01 那次 40 分钟课程变成长期资产的本地项目。它不承诺“自动发论文”，而是把选题、检索、验证、复现、实验、写作和审稿拆成可检查的阶段，让 opencode 承担高重复工作，让人保留研究判断和责任。

## 先看什么

1. [材料校订说明与术语表](docs/00_材料校订说明与术语表.md)：哪些转写被修正，哪些仍待核。
2. [课程结构化校订稿](docs/01_课程结构化校订稿.md)：把零散录音整理成完整方法论。
3. [Codex 科研方法深度剖析](docs/02_Codex科研方法深度剖析.md)：博士实际用了什么手法，哪些值得学，哪些不能照搬。
4. [可复用科研 SOP](docs/03_可复用科研SOP.md)：真正执行时遵循的阶段、产物和闸门。
5. [多角色提示词库](docs/04_多角色提示词库.md)：用于检索、反驳、复现、实验和写作的提示词。
6. [PACE-PC 报告审计](docs/05_PACE-PC报告审计.md)：现有 idea 报告中已核实、未核实和高风险的部分。
7. [科研内阁与任务调度](docs/07_科研内阁与任务调度.md)：总控台与专项对话如何分工、回传和升级决策。

## 这堂课的最终结论

该博士最有价值的能力，不是“换模块”，而是把研究限制翻译成一串连续决策：

`约束定义 -> 近年态势 -> 候选方向 -> 反驳与查重 -> 邻域迁移 -> 代码/数据/算力审计 -> 基线复现 -> 小规模试验 -> 完整实验 -> 论证与审稿`

需要保留的部分：目标会议和资源约束前置、优先公开数据与开源代码、反复追问 gap、主动让 opencode 自我否定、把 CPU 准备与 GPU 训练分开、先做低成本可行性验证。

需要删除或改写的部分：

- “20% 数据失败则全量必败”不成立。子集只能做 smoke test 和趋势筛选。
- “全程不需要编码”不成立。可以少手写，但必须能审查数据、实现、日志和结果。
- “换模块就是创新”只能描述某些论文的表面改动，不能作为研究质量标准。
- 不能先看到指标上涨，再倒推动机和 gap；这会造成事后叙事。
- AI 给出的论文名、分数、录取概率和算力成本都不是证据。
- 未发表论文、他人代码和私有数据不能因为方便而交给外部服务或传播。

## 开始一个新选题

在本目录运行：

```powershell
PowerShell -ExecutionPolicy Bypass -File .\scripts\new_topic.ps1 -Name "选题名称" -Venue "目标会议" -Deadline "YYYY-MM-DD"
```

脚本会在 `projects/` 下生成独立研究目录。随后让 opencode 先读取该目录的 `RESEARCH_CHARTER.md` 和根目录的 `AGENTS.md`，从当前阶段继续，而不是直接写模型或论文。

当前已建立一个种子项目：[20260902-CCFC选题](projects/20260902-CCFC选题/README.md)。其中只固化已知约束，未替你决定具体题目。

## 对话内阁

在本目录启动 opencode 后，主会话即“科研总控台”，负责统筹阶段状态、关键决策和分支调度；文献、数据集、选题红队、工程实验、写作审稿等专项工作由 `.opencode/agent/` 下的 5 个 subagent 承接。具体的职责、回传格式与权限边界见 [科研内阁与任务调度](docs/07_科研内阁与任务调度.md)。

## 目录约定

- `docs/`：课程资产、方法论和审计结论。
- `templates/`：每个研究阶段的固定模板。
- `scripts/`：新建选题和完整性检查脚本。
- `workflow/`：跨选题共用的状态与证据规则。
- `projects/`：实际研究项目，每个题目单独存放。
- `source_private/`：原始录音转写、截图和私密报告，只在本机保存，不进入版本控制。

## 使用边界

这套流程可以压缩检索、工程和文书时间，但不能替代：研究问题的真实性、实验公平性、结果复核、引用核验、作者贡献和投稿合规。opencode 是研究执行器与审计助手，不是论文责任主体。
