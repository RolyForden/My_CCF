# 科研 SOP 工作流设计说明

## 目标

把一次口头课程转成三层资产：可追溯的校订材料、可批判复用的方法论、可直接初始化的新选题项目。设计重点不是功能多，而是让每个结论都能回到证据，让每次失败都能沉淀为下一次决策。

## 三种可选形态

1. **单篇长文**：阅读方便，但执行时难以更新，也无法记录实验状态。
2. **纯脚本自动化**：启动快，但会把研究判断藏进脚本，不适合当前仍在学习科研的阶段。
3. **文档闸门 + 轻量脚本**：每阶段有固定产物和人工确认，opencode 负责重复劳动，脚本只负责建目录与校验完整性。

本项目采用第三种。原因是它既能让你反刍博士的思路，又不会把“AI 自动跑通”误当作研究能力。

## 架构

- `docs` 保存长期不随单个选题变化的知识。
- `templates` 定义每阶段最小产物。
- `scripts` 只做确定性的项目初始化和文件检查。
- `projects/<topic>` 保存每个选题的状态、文献、代码引用、实验和论文。
- `source_private` 保存课程原始材料，默认不进入 Git。

## 数据流

原始材料只读进入校订层；校订层产生课程事实与待核项；分析层把事实拆成可保留策略和风险；SOP 将策略固化为阶段闸门；新选题通过模板生成独立项目；所有实验结果再反向更新证据账本和决策日志。

## 失败处理

- 缺会议或截止日期：停在 INTAKE。
- 论文无法取得全文：证据最多标为 B，不得声称核实方法细节。
- baseline 无法复现：先记录环境与报错，不得直接更换到自写版本后声称复现。
- pilot 不通过：保留负结果，回到 IDEA，而不是修改主张迎合结果。
- 结果无法稳定复现：停在 PILOT/FULL_EXPERIMENT，不进入写作。

## 验收标准

- 原始材料完整保留且不被公开同步。
- 转写中的高置信误识别有校订，低置信项明确待核。
- 博士方法被拆成有效技巧、隐含假设和错误经验三部分。
- 新选题可以由脚本初始化，并通过校验脚本检查必要文件。
- SOP 不包含“必发”“保证录用”或无法证实的概率承诺。
