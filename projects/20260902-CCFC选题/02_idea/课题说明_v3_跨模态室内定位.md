# 课题说明 v3：面向室内重复结构歧义的跨模态定位

**中文题**：面向室内重复结构与部分视野的跨模态定位——候选竞争证据驱动的重排序与选择性接受
**英文题**：Candidate-Competitive Evidence for Ambiguity-Aware Cross-Modal Indoor Localization

> 版本：v3（在 v2「CUE-Loc」基础上，按博士意见重构定位）。文档日期 2026-09-05。方法效果与创新性需通过最小实验、对照与进一步查重验证，本文件不承诺录用。

---

## 0. 一句话方案

室内是 GNSS 拒止的标准场景：机器人丢失定位后，用单张 RGB 图像在先验 3D 点云地图中做地点/子地图级跨模态粗定位。针对「重复结构 + 部分视野」造成的定位歧义，学习把局部匹配证据区分为**共同证据**（多个候选都能解释）与**区分性证据**（能可靠地区分候选），并用同一套证据同时做两件事：

1. **候选重排序**（精度，主贡献）——用区分性证据改善 Recall@1；
2. **选择性接受**（决策，贡献之一）——当重排序也消不掉歧义时，暂不接受，而不是输出一个高置信的错位置。

**口径**：这不是「可信/拒判」单线作战，也不是再做一个更强的跨模态检索器；它锚定在一个具体场景难点上，接受决策只是两条贡献腿中的一条。

**定位**：在热门领域（跨模态定位）里，引入少人做的方法（检索歧义的接受决策）——既不是冷门单线，也不是正面拼召回。

---

## 1. 为什么是这个场景（动机，锚定难点）

**场景难点**：重复结构 + 部分视野。

- 一张有限视野的 RGB 只覆盖地图的一小部分；办公楼/医院/酒店里，墙面、门、柱在多个不同地点有几乎相同的结构。
- 此时大量**共同结构**会把匹配分数堆高，而真正能区分地点的少量证据被淹没。结果是 **top-1 分数很高、但位置错**——「自信但错的 top-1」。
- 当真正起消歧作用的结构（如一处转角）被遮挡时，这张图**根本不包含足以消歧的信息**。

**为什么「是否接受」比「找到位置」更重要**：

- 错误重定位（高分错配）进入位姿图是灾难性的，且事后极难定位；在 GNSS 拒止室内导航里，这不是精度问题，是安全问题。
- 在一个「要么对、要么错得离谱」的场景里，「这一帧敢不敢信、该不该降权/拒收」是决策级需求，不是精度后缀。因此「判断是否接受」在某些场景确实比「把 top-1 再排准一点」更重要。

**为什么这是整条路线的共同缺陷、而非某个 baseline 的短板**：描述子、几何结构、重排序做得再准，只要它在歧义未消时仍输出一个高置信位置，就都会错。这个失败不在某个方法，而在「只卷召回、不答是否可信」这一整条精度路线——所以需要引入「是否接受」这一决策维度。

## 2. 相关工作与 landscape（诚实版，全部 B 级已核，见证据账本 E-012~E-028）

**直接回答博士的问题「有没有人做过」**：核过了。方向拥挤——最近邻 **G2IA** 已做「跨模态检索 + 候选重排序」；「拒判」也有人做——**Localization Meets Uncertainty**（回归 percentile）与 **SafeVPR**（单模态序列 VPR 共形）。但「室内重复结构 + 部分视野的检索歧义 × 接受决策」这一**具体组合**目前没有直接工作。详见下方盘点。

### 2.0 子方向全景（回退一步铺开看）

跨模态定位 + 可靠性这条大线上，近两年的子方向：

- **跨模态检索/PR**（拥挤）：ModaLink / C2L-PR / InsCMPR / SceneGraphLoc / WildCross / G2IA——绝大多数据在户外/城市。
- **跨源基准**：WildCross、CS-Wild-Places——只给基准，不给接受决策。
- **退化感知 LIO / 定位完好性**：SuperLoc 等——拒收思想可迁移，但非检索，不作主战场。
- **配准可靠性**：Decision PCR / MATTER——几何级对错/误差，第二级近邻。
- **共形入机器人**：SafeVPR / Conformal-KF——渗透加速，但单模态序列 / 跟踪域。
- **检索的接受/拒判**（**刚开始有人碰**）→ 本课题落点：**检索 × 室内歧义 × 接受决策**。

### 2.1 跨模态检索/定位（本课题所在主线，**拥挤**）

ModaLink（IROS 2024）、C2L-PR（T-IV）、InsCMPR（ICRA 2025）、SceneGraphLoc（ECCV 2024）、WildCross（arXiv，venue 待核）、HOTFormerLoc（CVPR 2025）、VLM-Loc（arXiv，venue 待核）。方向近两年大量涌入，且**绝大多数跑在户外/城市场景（KITTI、NCLT、Oxford、HAOMO）**。

- **G2IA（arXiv 2606.15287）＝头号最近邻**：已做「跨模态检索 + 候选重排序」，与本课题任务结构高度重合；差异仅剩「城市 vs 室内」与「是否加接受决策」两点。

### 2.2 「接受/拒判」线（本课题的决策腿）

- **Localization Meets Uncertainty**（MDPI Technologies 2025，arXiv 2504.07677）：RGB+2D LiDAR 融合的端到端 3-DoF 位姿**回归** + percentile rejection（冻结模型 + 接受层）。任务不同（回归 vs 检索），但「无覆盖保证的离线阈值拒判」已有人做。
- **SafeVPR**（arXiv 2605.28048）：单模态视觉**序列** VPR + Mondrian 共形 FDR 保证。比「无保证阈值」更强，但单模态、序列、非室内。
- Decision PCR / MATTER：配准级（几何对错分类/误差回归），第二级近邻。

### 2.3 诚实结论（护城河盘点）

三片可能的护城河里：

| 候选护城河 | 结论 |
|---|---|
| 「跨模态检索任务结构」 | **不成立**：拥挤方向，G2IA 已做检索+重排序 |
| 「选择性接受/拒判」单独成线 | **不新颖**：回归 percentile（Localization Meets Uncertainty）与 VPR 共形（SafeVPR）都已有 |
| 「跨模态检索 × 室内重复结构/部分视野歧义的接受决策」组合 | **唯一未覆盖位，但属组件拼接风险位**，须用最小反例证伪后才能当卖点 |

## 3. 研究缺口（诚实口径）

缺口**不是**「没人做跨模态」，也**不是**「没人做拒判」，而是：**在部分可观的室内跨模态观测下，「局部匹配证据是否有候选区分力」尚未被系统回答，更没有被同时用于排序与接受决策。**

- 现有跨模态工作集中在户外/城市，未见针对「室内重复结构 + 部分视野」歧义的专门处理。
- 现有拒判工作要么在回归（不确定度）、要么在单模态序列 VPR（共形），没有针对「检索歧义」的接受决策。

**该缺口是否成立，取决于最小反例实验**（§7 表 0）：须验证「室内重复结构下高置信错 top-1」是真实、可测、可复现的失败，且 G2IA/SceneGraphLoc 类方法在此失败下仍高置信。若现象不存在或基线已无此失败，本方向淘汰，回到既有点云退化主线。

## 4. 三个贡献（双支柱）

1. **（精度，主贡献）候选竞争证据（三层精度结构）**：区分共同证据与区分性证据，在局部证据层跨候选比较其消歧力，用于候选重排序（Recall@1）。落地为三层——局部跨模态支持 → 候选竞争 → 重排序头（§5 M1–M3），核心在第二层的「证据区分度」，不是再学一个更强的检索器。
2. **（决策，支柱之一）共享证据的选择性接受**：同一证据表示用于接受决策，考察支持强度 / 区分程度 / 支持范围三个维度；当重排序也消不掉歧义时暂不接受——在这些场景「是否接受」比「找到位置」更重要。
3. **（边界）诚实口径**：地点/子地图级粗定位，非 6DoF 位姿、非安全保证；接受阈值在**独立校准集离线选定**，不声称覆盖率或分布漂移保证。

**强调**：这是「具体场景难点」驱动的双支柱，接受决策只是其中一条腿，不是把「可信」当成整个课题。

## 5. 方法设计（具体模块）

整体管线：

```
单张 RGB + 先验 3D 点云地图
   → [冻结] 跨模态检索器 → Top-K 候选
   → M1 局部跨模态支持（patch↔region，允许无对应）
   → M2 候选竞争（共同 vs 区分性证据分离）
   → 共享证据表示
       ├─ M3 重排序头：更新候选得分 → Recall@1（主贡献）
       └─ M4 接受头：证据不足则暂不接受（轻量，次要）
```

### M1 局部跨模态支持模块

- 输入：图像 patch 特征（**冻结**视觉塔，DINOv2/CLIP）；候选地图的局部几何特征（点/超点，**冻结**点云塔）。
- 结构：一个**可学习投影层**把两侧映射到同一跨模态匹配空间，算 patch→3D region 支持分数。
- 输出：每个局部图像区域对每个候选的「支持矩阵」。
- 冻结/训练：两塔冻结、缓存特征；只训投影层。显式允许无对应，避免把遮挡、模态不一致或无结构区域强行配到候选上。

### M2 候选竞争模块（核心，真差异点）

- 输入：M1 的支持矩阵（对 Top-K 候选）。
- 结构：小规模集合交互（跨候选归一化或小注意力层），计算每个局部证据的**区分度**——一个证据若被多个候选同样支持则降权（共同证据），若唯一支持某候选则升权（区分性证据）。
- 输出：区分性加权的证据表示（共享给 M3/M4）。
- **为什么是差异点**：G2IA 的重排序比较的是「候选最终得分」，本模块比较的是「局部证据对不同候选的支持差异」，且发生在局部证据聚合之前。

### M3 重排序头（主贡献）

- 输入：M2 的区分性加权证据。
- 结构：轻量聚合 + 候选得分更新。
- 输出：新候选排序 → Recall@1 提升（主实验表 2）。

### M4 接受头（轻量，次要）

- 输入：同一共享证据表示，只读三个量：支持强度 / 区分程度 / 支持范围。
- 结构：轻量头 + **独立校准集离线阈值**。
- 输出：接受 / 暂不接受（表 3）。参数与叙事占比最小。

### 训练与冻结纪律

- 只训练 M1 投影层、M2 交互层、M3/M4 两个轻量头；两塔冻结缓存，减少重复特征提取。
- 训练/校准/测试三部分严格分离；部署时固定参数与阈值，不依赖在线真值、不做 ACI 在线更新。
- 候选间比较发生在局部证据聚合之前；对同一地点的相邻/高度重叠地图片段按地图坐标分组，避免把等价正确候选当竞争。

## 7. 最小实验闭环（先证伪，再投入）

| 表 | 回答的问题 | 指标/对照 | 阶段 |
|---|---|---|---|
| **表 0（闸门）** | 室内重复结构下「高置信错 top-1」现象是否存在？基线是否已无此失败？ | 在 3RScan 重复结构子集上统计；G2IA/SceneGraphLoc 基线室内表现 | 立项闸门 |
| 表 1 | 基线召回复现 | Recall@K | 管线 |
| 表 2（主图） | 候选竞争重排序是否优于独立重排序 / 分数阈值？ | Recall@1/K；对照三组：原检索器+重排序 / +分差阈值 / +轻量接受头 | 主实验 |
| 表 3 | 接受决策是否在「消歧失败」样本上起效？ | 风险—接受比例曲线；固定风险下正确接受率、固定接受比例下错误率 | 主实验 |

**指标定义**（避免混用）：接受错误率＝「错误且被接受的查询数 / 全部被接受的查询数」；接受比例＝「被接受查询数 / 全部查询数」；同时报告初始 Recall@K 以界定可改善空间。接受模块在自然候选分布（含真实地点不在 Top-K 的样本）上评价。

## 8. 技术栈与算力

- **已有**：Ubuntu、ROS2、RViz、evo、单卡 4090（冻结双塔 + 轻量模块为小时级，富余）。
- **需搭建**：PyTorch、Open3D、SceneGraphLoc 官方管线、3RScan/3DSSG 数据；图像塔 DINOv2/CLIP 预训练权重。
- **明确不做**：ACI/覆盖率保证、仿真渲染 sim-to-real 管线、位姿图集成 demo（后者为冲刺项，非主线）。

---

## 9. 关键风险与诚实边界

1. **G2IA 撞车**：若红队证明「室内歧义」不是真缺口、或 G2IA 在室内重复结构下同样有效，本方向淘汰。
2. **组合缺口可能被当成「换场景 + 加个拒判头」的拼接**：须用最小反例 + 机制消融证明「检索歧义拒答」本质区别于回归 percentile（Localization Meets Uncertainty）与单模态 VPR 共形（SafeVPR）。
3. **代码可得性**：G2IA / C2L-PR / SceneGraphLoc 官方代码本批未见/未核到，若 BASELINE 拿不到代码，对照实验将退化为自实现基线，需在进入 BASELINE 前确认。
