# idea 报告模板

> 来源：博士《FocalAfford final idea report》（2026-09-10）+ 博士《科研决策规则与经验汇编》第 10 节。
> 配合 `GATE.md` 使用：GATE 管「方向能不能立」（真实 gap / 公开数据 / 开源基线 / 最小证伪），本模板管「proposal 怎么写才防缝模块」。
> 用法：新方向动笔前，先照本模板把 8 节写全，尤其是第 4 节（证伪基线）和第 7 节（失败退路），写不全就说明方向还没想清楚。

---

## 0. 一句话概括

（一句话说清：把哪个领域的什么机制，迁移/组合到哪个任务，改良什么。）

## 1. 核心问题（gap 锚定具体缺陷）

- **背景**：任务演进，3-4 步（从早到晚，点名 + 一句贡献）。
- **现有方法留下的问题**：**指名道姓**说出某个现有方法的**某处具体缺陷**——是「特征融合而非局部重渲染」这类可证伪锚点，不是「重复结构导致混淆」这类现象描述。
- **核心问题一句话**：由上述缺陷导出，必须能在实验里直接回答。

## 2. 核心思路

- **定位声明**：明确写「创新类型属于跨领域机制迁移＋面向任务的组合改良，不是全新范式」。组合是否有效，取决于机制能否赢过第 4 节的直接组合基线。
- **总体结构**：一张 ASCII 图，标清主框架、新增机制、推理时剩什么（推理删掉训练期模块不单列为创新）。

## 3. 三项拟贡献

- 一个模块 = 一个贡献点；三个贡献点 = 一个贡献的三个子点（新问题 / 新机制 / 新评测），不是三个独立贡献。
- 每个贡献后注明「这是迁移 / 组合 / 改良」的哪一种。

## 4. 关键简单组合基线（证伪基线，最值钱）

- 每个新机制，动手前先写「最简基线 = 去掉该机制的版本」。
- 例子（FocalAfford 范式）：
  - `框架 + 直接组合（无新机制）` → 证伪「新机制是否必要」；
  - `框架 + 等价重加权（不传新特征）` → 证伪「是不是只是标签重加权」。
- 规则：**机制必须赢过它的最简基线，才算成立**；赢不过就删，别硬解释。

## 5. 数据集 + 注意事项

- 数据集 / 规模 / 用途（主数据集 + 第二验证集 + 可选鲁棒性）。
- 预注册坑：划分按对比工作协议固定、缺标注不据此宣称泛化、标签性质别改写（如软热图别改成抓取接触标签）。

## 6. 分阶段实验路线

- **A 阶段：筛组合**。每个配置对应一个假设 + pass/fail（如「A3 稳定优于 A1 和 A2 才支持互补；A1 最好则删语境模块；A2=A3 则不能声称局部视觉起作用」）。
- **B 阶段：验机制**。固定最佳组合，对照第 4 节的最简基线，逐个证伪机制。
- **C 阶段：完整对比 + 泛化**。seen/unseen、第二数据集、强基线；统一评测代码，不拼表格数字。

## 7. 成立条件 + 失败退路

- 写死「三项成立条件」。
- 写死退路：全成 → 完整故事；只成一项 → 收缩为该机制（创新降级）；第一项都不成 → **停止继续堆模块**。

## 8. 算力与周期

- 单卡条件（对标主框架的显存/epoch/bs）。
- 省钱设计：冻结主干 + 缓存教师特征 + 分阶段验证，避免每个对照都全量训练。
- 建议执行顺序：数据与基线核查 → A 阶段筛选 → 只对最佳组合做 B/C → 核心成立后再扩展。
